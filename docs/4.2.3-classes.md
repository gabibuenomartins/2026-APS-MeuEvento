O diagrama de classes apresenta seis classes principais do sistema MeuEvento: Festa, Organizadora, Cardapio, Decoracao, Atracao e ItemFesta.

A classe Organizadora está relacionada à classe Festa, pois uma organizadora pode organizar festas. A classe Festa está relacionada ao Cardapio, à Decoracao, às Atracoes e aos Itens da Festa, pois esses elementos fazem parte do planejamento do evento.

Não foi identificada necessidade de herança, pois as classes não representam tipos especializados de uma classe geral.

A composição será considerada entre Festa e ItemFesta, pois os itens registrados para o planejamento pertencem ao evento. Essa decisão é provisória e deverá ser confirmada com a cliente: se a festa for excluída, os registros dos itens também deverão ser excluídos?

As demais relações são associações comuns, pois representam informações relacionadas à organização do evento, sem afirmar que uma classe deixa de existir quando outra é excluída.

Teste de objetos

Para testar a modelagem, foi considerada uma situação hipotética de organização de uma festa de aniversário.

Ana está organizando uma festa, define a data e o horário, registra uma atração e acompanha os itens que já foram organizados.

Objeto	Classe	Valores
ana	Organizadora	nome = "Ana"
festaAniversario	Festa	data = "20/12/2026", horario = "19:00"
cardapioFesta	Cardapio	descricao = "Salgados, bolo e bebidas"
atracaoMusical	Atracao	nome = "Música ao vivo"
itemDecoracao	ItemFesta	descricao = "Decoração da mesa", organizado = true

Ligações: ana organiza festaAniversario; festaAniversario possui cardapioFesta, atracaoMusical e itemDecoracao.

O que o teste confirma

Uma Organizadora pode estar relacionada a uma Festa.
Uma Festa pode possuir informações de cardápio, atrações e itens planejados.
Um ItemFesta pode ter seu estado de organização acompanhado.
A situação demonstra a necessidade de armazenar informações diferentes para cada elemento do planejamento.

O teste utiliza uma situação hipotética e ainda deverá ser validado com as informações da cliente.

Toda operação tem origem?

As operações apresentadas possuem origem nos requisitos funcionais ou na necessidade identificada na seção 4.2.1. A conferência com o fluxo principal da 4.2.2 ainda deverá ser realizada para confirmar a correspondência com os passos da especificação.

Todo passo do sistema tem casa?

Os requisitos de definição de data e horário, organização de comidas e bebidas, decoração, registro de atrações e acompanhamento possuem classes e operações correspondentes.

O que a modelagem mudou?

A modelagem permitiu identificar as principais informações que o sistema MeuEvento precisa armazenar. Também mostrou a necessidade de confirmar com a cliente como os itens da festa devem ser acompanhados e o que acontece com esses registros quando um evento é excluído.
